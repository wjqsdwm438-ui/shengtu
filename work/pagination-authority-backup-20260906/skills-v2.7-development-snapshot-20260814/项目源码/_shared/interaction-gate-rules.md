# 交互 Gate 必要性与授权复用规范

## 根因
旧规则把依赖检查顺序写成逐项用户批准；“一次一个问题”缺少提问前的必要性检查；单产物完成立即停止与端到端授权并存；流程图与反例继续强化机械检查链。结果是有规则名称、无新增决定的重复阻塞。

## 执行协议
1. 从当前请求和有效记录识别：已批准对象、版本、用途、范围、排除项与未决项。在现有简报/确认记录中维护，不另造用户填表或统一状态台账。
2. 分类：内部可判定项直接完成；已批准且无变化项沿用；真正新增的用户专属决定或授权缺口才进入 Gate。授权必须有原话或有效记录支持，不能把模型建议升级为批准。
3. 先展示实质方案，再审阅。一个完整分页方案应包含原文范围、教学任务、候选路由、Non-A与未决事实，不先让用户批准抽象阶段名称。已有范围不重复提交；多个独立设计决定不能借“合并”偷渡批准。
4. 必要提问格式：当前阶段与结果；已沿用的批准；唯一未决差异及证据；具体推荐与影响；待用户决定的一个问题。解释回答如何改变下一动作。无差异、无动作影响，不得发问或停止。
5. 无实质 Gate 时在授权内继续；正式产物写入前说明文件/分区、是否改旧文件、下游接收什么。目标和范围已有明确授权则不再问；新增或扩大写入才询问。分析授权不冒充写入授权。
6. 同范围确认直接沿用，变化仅重确认受影响项。用户“本次不评价/另行分析”表示保留开放，不是否定整项，也不是同意附带方案。
7. 用户拒绝重复回答：回查证据，撤回冗余问题并继续已授权工作；确有未决硬 Gate 时说明新方案、未决差异及具体停止原因，不能宣称全部获批，也不能原句重问。

## 授权边界
“按规则执行到停止点/全流程测试”足以授权范围内分析及阶段推进，不必反复问是否继续。它不自动批准未展示的分页、设计、参考角色、付费或有隐私影响的外部动作、生图、代表页扩批、局部重做或最终成品。联网检索许可不是网上图片直接使用或重绘许可。素材存在不等于用途获准。

## 场景验收
- 已批准正文全范围且确认引入/结尾Non-A：模型分析主体路由并提出具体分页，不再问是否处理主体或是否进入A线。
- Non-A获批但制作方式不评价：只沿用Non-A，制作方式保持未定，不阻塞主体分析。
- 本地原稿能回答内容范围：先读，不让用户重述。
- 文稿无时间轴需求：时间字段不适用，不索要音频。
- 首次提出8页分页：可请求一次实质审阅，未批准不写冻结S区。
- 用户拒绝重复问题：不推定8页方案获批。
- 已批准8页原方案且未改变：不重问；新增第9页或改变分段只审受影响差异。
- 端到端授权但未明确写入目标：继续分析，写入时提交具体目标和范围的授权缺口，不偷写文件。
- 已明确授权目标文件及分区：告知后写入，不再问同样是否执行。
- 代表页生成/扩批/最终定稿：保留各自明确 Gate，不用“减少追问”取消。

## 验证边界
离线检查只能验证入口、措辞和流程图契约，不能证明真实会话行为已稳定。按以上场景进行后续实际测试；失败按最早产生错误的规则定位，不叠加更多确认层。
