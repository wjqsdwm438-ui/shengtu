# 课程视觉生产工具 V2.7.1

本目录是项目的**真正源码根目录**。外层目录仅保存 2026-08-14 开发快照的交接包装、清单与来源证据，不是运行根目录。

## 当前状态

- 版本定位：V2.7.1 开发基线收口。
- 部署状态：仅供本地开发和验证，**未安装或注册为全局 Skill**。
- 依赖边界：检查工具仅使用 Python 标准库；本次基线不安装第三方依赖、不修改全局配置、不推送远程，也不直接接入需要密钥或费用的 API。
- 路径约定：文档、脚本和 Skill 只使用相对项目根的路径，不依赖固定盘符或固定安装位置。

## 流程与职责

主流程为：

```text
S线 -> A线 -> A审 -> B线（动态分批） -> C线执行适配器 -> C线生成/局部修改 -> 按课程原顺序组装
```

| 阶段 | 目录 | 主要职责 |
| --- | --- | --- |
| S线 | `stage-sline-srt-media-routing/` | 原文/时间码、事实、素材与媒体路由，不设计版式 |
| A线 / A审 | `stage-aline-course-visual-routing/` | 教学目标、教学关系、必呈信息和语义边界；A审只核对教学与事实 |
| B线 | `stage-bline-production-handoff/` | 基于真实模板证据形成唯一可执行方案，动态分批并指定代表页 |
| C线 | `stage-cline-gpt-image-execution-feedback/` | 执行适配、GPT Image 生成反馈及同结构局部修改闭环 |
| Algorithm Lite | `stage-algorithm-lite-companion/` | 为各阶段提供轻量、非越权的确定性检查 |

原 T线不再是独立阶段。其提示词编译、素材注入和参数校验职责已并入 C线执行适配器；旧入口只用于迁移识别，不属于当前运行链。Algorithm Lite 是伴随检查层，不替代 S/A/A审/B/C 的业务判断，也不恢复固定比例、固定批数或可编辑版式规格。

## 页面简报与批次

- 每页只维护一份 S/A/B/C 分区的页面简报；各阶段只追加自己的分区，不重新转述上游结论。
- B线不按页码默认连续生产，而是结合外层模板、教学关系、语义视觉载体、参考依赖和生成方式动态分批，不预设批数。
- 每批先确认一张具有典型信息密度和核心教学关系的代表页，再展开本批其余页面；不同批次使用隔离的 C线对话上下文。
- 跨页复用局部骨架必须证明两页具有相同教学关系和相同语义视觉载体；“效果好”“风格统一”或“页码相邻”均不足够。
- 页面不使用固定图片占比。只检查图像教学任务、视觉焦点、可读性、信息关系、背景竞争和必呈内容空间。
- 完整交接规则见 `_shared/page-brief-batch-execution-rules.md`，版式1/2的实现证据边界见 `_shared/template-realization-evidence-rules.md`。

## 渐进式读取机制

- 每个阶段默认只读取当前 `SKILL.md`、用户输入和该阶段必需的上游交接。
- references、templates、examples/anti_examples 按“规则判断、正式结构、失败证据”分别触发，不得整组预读。
- 每次只围绕一个未决问题扩展一个来源；读取关键术语后立即确认当前含义、直接证据和剩余未决项。
- 当前阶段判断充分、到达阶段边界或需要用户作出选择时立即停止，不自动预读下一阶段。
- 完整审计规则见 `_shared/progressive-reading-protocol.md`；普通业务任务不需要默认加载该文件。

## GPT Image 合同

- 主流程能力名称为 **GPT Image**，当前请求模型为 `gpt-image-2`。
- C线执行适配器默认只输出一套中文执行提示词，不再生成英文版或三平台版。
- “请求模型”不等于“实际执行模型”。只有执行工具或 API 的回执明确报告模型时，才能记录实际执行模型；未报告时必须写“未报告”。
- 完整课程视觉页默认使用不透明背景。
- 素材层、人物或物体抠图、可叠加组件等任务可按需请求透明背景，并使用支持 Alpha 的 PNG 或 WebP。透明背景能力按当前合同标记为 preview，不应表述为所有任务的默认能力。
- 即梦、nanobanana 与旧三平台提示材料已降级为历史证据，位于 `legacy/platform-prompts-v2.7.0/`，不属于当前运行依赖。

## 参考锁定带字页与Remotion资产

- 参考文件夹可作为正式输入；B线选择一张主版式参考和最多两张辅助参考，并由用户确认后冻结到当前批次。跨批复用仍需重新核对教学关系和参考角色。
- 固定版式任务不再由 A01–A21 旧页型路由；A线只冻结教学语义，B线基于确认的真实参考形成一个 `reference_locked_full_page` 主执行方案。
- B线必须保留选定参考图的真实路径，C线执行适配器必须校验并实际附加；禁止只凭“参考原图”文字重构或自动带入历史会话图片。
- 第一版由 GPT Image 直接生成完整带字画布；文字必须逐字准确，初次生成后最多进行两次局部修订，不使用确定性文字覆盖。
- 通过检查的完整页先进入 `full_page_candidate`，只有用户确认后才成为 `final_course_visual`。
- 项目可为外部Remotion流程准备透明前景和按需拆层合同，但不生成Remotion代码或执行视频渲染。
- 透明前景只能从已确认成品派生并经过显性Gate；Alpha失败不得降级为不透明图。

## 本地检查

在本目录中运行：

```powershell
python run_all_checks.py
```

默认检查应保持只读，临时产物写入系统临时目录。只有在确需刷新仓库验证证据时才显式运行：

```powershell
python run_all_checks.py --update-evidence
```

检查范围包括现有 Python 工具及正反例、五个活动 Skill 的 frontmatter 与 `agents/openai.yaml` 最小 schema、页面简报/动态批次/C适配器合同、渐进式读取入口约束、参考锁定/Remotion合同用例、固定旧路径、当前 GPT Image 契约、历史目录边界和 UTF-8 编码。任何失败均应返回非零退出码。
