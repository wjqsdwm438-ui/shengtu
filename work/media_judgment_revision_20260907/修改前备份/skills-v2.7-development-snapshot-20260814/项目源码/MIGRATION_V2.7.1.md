# V2.7.1 迁移说明

## 当前增量｜2026-09-07 分页重构

本节优先于后续历史迁移叙述中的S/A/A审固定阶段。默认入口改为A，包含输入整理、教学分析、必要承载核验、明确分页和内部复核；B保留具体视觉生产设计。S是兼容输入工具，不是默认阶段；独立审者仅用户明确要求时执行，不定义自动触发条件。

- 不重写用户原稿、旧S源引用或有效Non-A/正文准入；旧候选页界与审核通过不能自动迁成新A方案。
- 新A计划引用真实源路径/版本与精确跨度，分页后创建page_id；候选拆合只更新A的映射，不恢复独立S迁移流程。
- `course_visual_page_brief/v2.7`保留页面容器名，新增 `a_pagination_plan`（`course_visual_a_pagination/v1`）与A/B `pagination_ref`；当前源证据和内部复核存在于A计划，不再以 `s_section.status=confirmed` 或 `a_review_status=passed`作为默认就绪依据。
- 旧固定S/A_review workflow不作为新生产就绪合同；先在现有A产物中完成真实分页重审及内部复核，再补当前引用。不得将历史9单元简单改名以通过新检查。
- 页界/页数/正文归属或教学关系变化由A处理，B只能反馈证据；旧新页映射及受影响下游状态保留，无关批准继续有效。
- 本轮只改项目内规则、模板、流程图和校验；不改外层快照、全局配置或既有生图/参考/代表页/定稿授权，不执行真实课程生产。
- 本轮前状态已保存在工作区 `work/sab_refactor_20260907/before/`，实际变更清单及验证见同目录实施记录；回滚逐文件对照该备份，不用Git基线覆盖既有未提交修改。新增文件单列，回滚前核对是否有后续变动。

结构细节见 `_shared/pagination-plan-contract.md`；脚本通过只说明其实际验证事项，不说明教学质量或授权真实性。以下章节保留历史迁移记录。

## 3. GPT Image 与独立 T线合同迁移

### 当前合同

- 能力名称：GPT Image
- 当前请求模型：`gpt-image-2`
- C线执行适配器输出：单套中文执行提示词和实际资产附加清单
- 实际执行模型：仅依据工具或 API 回执填写；无回执时记录“未报告”
- 完整课程视觉页：默认不透明
- 素材层、抠图、可叠加组件：按需请求透明背景，格式为 PNG 或 WebP，Alpha/透明背景能力标记为 preview

### 历史合同

即梦、nanobanana 及旧三平台提示材料迁移到：

```text
legacy/platform-prompts-v2.7.0/
```

该目录是只读历史证据：当前 Skill 不自动读取，不作为默认示例，也不属于运行依赖。当前检查器只验证其文件存在、UTF-8 编码和迁移说明完整，不把历史正文中的旧术语当作当前合同。

原 `stage-tline-prompt-translation/` 的有效职责只有提示编译、素材注入和参数校验，迁入 `stage-cline-gpt-image-execution-feedback/` 的执行适配器。迁移后：

- B线直接把唯一主执行方案交给 C线；
- C线先校验页面简报、真实素材路径和必填字段，再编译提示；
- 空字段、素材缺失或设计矛盾必须停止，C线不得自行补设计；
- 旧 T线目录、模板、元数据和活动链接从当前运行范围移除，历史追溯使用 Git 标签。


该结构只是 Skill 的界面登记与调用策略，不改变各阶段业务权限，也不会开启隐式调用。

- 原分阶段重复卡片迁为单页 S/A/B/C 分区简报；各阶段只维护自己的分区，发现上游错误时退回原责任阶段修正。
- 课程原始页码和顺序继续保留，但生产顺序由 B线根据真实机制动态分批，不预设批数。
- 每批先执行并确认一张代表页，不同批次隔离 C线上下文；代表页确认不等于最终成品确认。
- 旧的跨页构图沿用只有在 B线证明相同教学关系和相同语义视觉载体后才能迁移；仅因效果好或页码相邻的继承全部失效。

页面简报和批次合同见 `_shared/page-brief-batch-execution-rules.md`，指定版式1/2样片的能力边界见 `_shared/template-realization-evidence-rules.md`。
