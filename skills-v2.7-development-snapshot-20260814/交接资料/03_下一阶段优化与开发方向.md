# 下一阶段优化与开发方向

## 建议阶段名称

V2.7.1：开发基线收口。

这一阶段先让当前系统“可迁移、可验证、可回滚”，不急于升级为 V2.8 或增加外部依赖。

## 第一批：基线收口

1. 初始化正式 Git 仓库，提交当前开发快照并打基线标签。
2. 确定唯一项目根目录策略：相对路径、环境变量或安装时注入，三选一。
3. 统一 T线默认行为为 Image2-first，并同步共享总控、SKILL、模板、示例和 UI 元数据。
4. 将历史测试日志统一转为 UTF-8，并保留转换前备份和验证证据。
5. 统一 6 个 `agents/openai.yaml` 的 schema 和显式调用策略。
6. 增加根级 `run_all_checks.py`，一次运行全部离线验证。

## 第二批：测试增强

1. 文字预算增加 60/61、120/121、180/181 边界样例。
2. SRT 增加空文件、UTF-8 BOM、无序编号、异常时间码、中英混排、长停顿样例。
3. A01 骨架增加字段存在但内容无效的反例。
4. 复杂度评分增加单因素和多因素组合矩阵。
5. 为模板的必填字段建立 JSON/YAML 合同验证。
6. 自动扫描固定路径、过期术语、“视觉样张误称定稿”等问题。

## 第三批：规则型自动化

### ALG-B01

把生产可行性评分实现为轻量脚本，输入冻结字段、文字可控性、素材保留、参考冲突、候选差异和失败风险；输出证据分、缺项和是否建议进入 T线。

### ALG-C01

先做规则型失败分类器，不引入模型训练。输出失败类型、保留项、仅修改项、禁止修改项、最小修改提示和建议回退阶段。

## 第四批：真实项目闭环

至少选择：

- 5 个 SRT 媒介分流任务。
- 5 个课程单页设计任务。
- 5 个失败视觉样张局部修改任务。

每个任务维护 Manifest，统计 S线误路由、A审退回、B线候选趋同、T线首轮失败和 C线修改越界原因。

## 暂缓方向

- PPTX、HTML、Remotion、MP4 自动生产。
- 自动安装插件、MCP 或第三方依赖。
- 全自动多代理生产链。
- 无用户 Gate 的三平台并行执行。
- 将规则评分宣称为最终自动决策。

这些方向需要单独评估依赖、费用、隐私、维护和回滚成本。

## V2.7.1 完成标准

- 有可追踪 Git 基线。
- 新电脑上能从任意根目录运行现有 4 个脚本。
- 一条命令完成全部离线检查。
- 6 个 Skill 元数据和路径一致。
- 全部文本证据采用统一 UTF-8。
- 至少 5 个真实任务完成端到端 Manifest。
- 未经用户确认时，所有输出都保持“视觉样张”状态。
