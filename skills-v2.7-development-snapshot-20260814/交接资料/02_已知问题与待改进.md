# 已知问题与待改进

## P0：影响换机和继续开发

1. **路径不一致**：当前源码可能位于其他目录，但多个 `SKILL.md`、`agents/openai.yaml` 和历史日志仍写死 `D:\codex\skills-v2.7`。
2. **未正式安装**：磁盘上存在 6 个 Skill 目录不等于 Codex 已注册或启用。
3. **T线契约不一致**：详细 SKILL 规定默认 Image2-first；共享总控和 T线界面元数据仍有默认三平台旧表述。
4. **日志编码不统一**：多数根级 `.stdout.json` 为 UTF-16 LE，不符合统一 UTF-8 工具链预期。
5. **版本管理缺失**：当前可见 `.git` 是空目录，不能提供提交历史、分支、标签或可靠差异证明。

## P1：工程化不足

1. 没有根级开发说明和统一测试命令。
2. 没有自动检查 Skill frontmatter、`agents/openai.yaml`、内部链接和模板字段。
3. `stage-algorithm-lite-companion\agents\openai.yaml` 的结构与其他五个 Skill 不一致。
4. ALG-B01、ALG-C01 尚未脚本化。
5. 现有测试主要是固定样例，不是完整回归测试框架。
6. SRT 索引是确定性时间块，仅供人工语义复核，不是真正自动语义分段。

## P2：规则质量仍需真实项目验证

1. A01-A21 的边界需要更多真实反例。
2. B线两个候选是否真正不同，目前主要靠文本规则约束。
3. 参考图继承、素材保留和设计系统冲突缺少量化证据。
4. T线提示词对不同 Image2 版本的稳定性尚无系统统计。
5. C线局部修改是否越界，需要真实视觉样张闭环验证。

## 处理原则

- 先修一致性和可验证性，再新增大功能。
- 不因换电脑而顺手批量修改全局 Skill 或配置。
- 所有路径迁移、正式安装和注册操作单独设 Gate，并准备回滚。
- 不把历史日志编码问题误判成中文内容损坏；转换前先按正确编码读取。
