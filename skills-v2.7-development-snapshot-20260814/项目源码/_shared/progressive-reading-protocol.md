# Progressive Reading Protocol

本协议用于审计或维护 V2.7 Skill 的读取行为。普通业务任务不必默认读取本文件；各阶段 `SKILL.md` 已包含执行所需的精简版规则。

## 目标

用最小充分证据完成当前阶段判断。读取范围由尚未解决的决策驱动，不由“可能有用”驱动。

课程任务默认从A核对源文、备注/正文、Non-A和素材对应开始；不由版式反推教学内容关系。A在分页期间读取获准模板/素材的必要承载证据，B在具体视觉设计前沿用有效证据并补充实现细节。先读本地能够消除信息差的材料；不能以询问用户代替可完成的本地阅读。

版式资产仅作为文字检查清单分为六类：固定外层母版、母版预览、内层排版参考、内容或素材参考、失败诊断图、无关或拒绝参考。先说明分类依据和结果，并检查遗漏、重复归类、失败图误作参考及拒绝项进入下游。分类核对由模型内部完成；已有参考用途授权直接沿用。只有具体资产用途存在歧义或改变时才询问受影响决定，不按六个类别逐项索批。此分类不要求新增 Schema、状态机或自动校验器。

## 四层来源

1. **入口层（必读）**：当前阶段 `SKILL.md` 与用户当前输入。当前页页面简报的必要上游分区只有在本阶段依赖时才属于入口层；不得为了“完整”读取或重述其他分区。
2. **规则层（按需）**：只有某个具体判断无法由入口层完成时，读取该判断唯一对应的 reference，优先定位术语或标题所在的小节。
3. **结构层（按需）**：只有需要生成或校验正式结构化交付时才读取 template；普通解释、路由结论或缺失信息 Gate 不读取模板。
4. **证据层（例外）**：只有判断仍不稳定、出现对应失败、用户要求示例或需要回归证据时，才读取一个直接匹配的 example、anti-example 或 Algorithm Lite 规则。

`legacy/` 永远不是自动扩展层，只能用于用户明确要求的迁移、审计或历史追溯。

## 单步扩展循环

每次只扩展一个能够回答当前未决问题的来源：

1. 写明当前阶段、当前交付物和唯一未决问题。
2. 先在已读内容中查找答案；已有充分证据时停止。
3. 需要术语定义时，先搜索精确术语或标题，再读最小相关小节；不要直接全文读取相邻阶段或整个资料树。
4. 读取后立即执行“快速确认”。
5. 只有快速确认仍指出一个具体未决问题时，才进入下一次单步扩展。

不得为了“更全面”“可能相关”或预防未知问题而连续读取多个 reference、模板、示例或相邻阶段 Skill。

## 单问题追问顺序

本地读取仍无法消除信息差，或剩余事项属于用户的授权和设计决定时，才进入用户 Gate。每次只提出一个问题，一个问句及其相邻说明不得混入第二个待确认事项；收到回答后，再判断是否需要提出下一个问题。模型可以给出一项推荐及理由，但推荐不能自动成为冻结结论。

PSD 或其他分层母版不可用时，不得自行改用扁平 PNG 继续执行。先说明非分层参考的具体限制，再以一个独立问题询问用户是否接受。

## 快速确认

关键术语或规则读取后，只用自然语言在内部核对：当前阶段是什么、正在确认哪一个术语或判断、直接证据来自哪里、该术语在当前任务中是什么意思、是否还剩一个具体未决问题、下一步是否需要再读一个文件小节，以及是否已经足够停止。

这不是可持久化状态、Schema 或统一工作流字段。默认不要求增加用户可见篇幅；仅在用户要求路由审计、需要解释读取依据或进入用户 Gate 时输出简短说明。

## 停止规则

满足任一条件立即停止扩大读取：

- 当前阶段的路由、风险或交付物已经能由直接证据完成；
- 新来源不会改变当前决定，只会补充背景知识；
- 已到达用户本次授权的阶段边界；A的输入整理、承载核验和内部复核不是独立阶段，不在这些内部步骤后机械停止；显式仅请求S输入整理时才停在该请求边界；
- 剩余问题属于用户控制项，继续读本地资料也无法替用户决定；
- 需要的只是输出格式，读取对应模板后不再连带读取示例。

单轮默认只执行用户当前请求的阶段。只有用户明确要求端到端流程，或明确要求继续到下一阶段时，才跨阶段读取；跨阶段后重新从该阶段入口层开始。端到端授权不跳过每批代表页确认，也不允许在不同批次复用同一 C线上下文。

未获执行授权时默认保持计划状态。明确端到端授权覆盖所请求范围内的分析与阶段推进，不因完成一个内部步骤而停止索批；正式写入仍核对目标和范围，生图仍核对具体授权，实质 Gate 不得跳过。

## 用户 Gate 与读取确认的区别

- **读取确认**用于核对模型是否正确理解术语和规则，通常内部完成，不打断用户。
- **用户 Gate**只用于缺少用户拥有的信息或授权，例如素材重绘权限、参考图角色、必须展示的原文或结构变更选择。
- 不得把“还没读更多文件”误报为用户 Gate，也不得用继续读取替代必须由用户作出的决定。
- 设计方向、版式选择、参考继承、文字策略、提示词方向及生图选择的最终决定属于用户；模型只能分析和推荐。

## 交互 Gate：先判必要性，再提问

- “核对/快速确认/逐项检查”默认是模型内部工作，不等于逐项向用户索批。提问前先核对当前指令、有效确认和本地证据；相同对象、版本、用途和范围没有变化时沿用，不换名称重问。
- 只有存在会改变下一动作的用户专属决定或缺失授权才提问；必须说明具体未决项、已有结论、推荐方案、影响及被阻塞动作。不能说明回答将改变什么，不得阻塞。
- 一次一个问题约束的是实质决策，不是把一个完整方案拆成机械确认链。先给出可审阅的具体方案；同一范围内的路由清单可随分页方案一并审阅，不另问“是否继续/是否进入下一线”。
- “执行全流程/按规则自行执行到停止点”覆盖所请求范围内的分析与阶段推进；没有实质 Gate 时继续。正式文件写入仍核对目标和写入范围；范围已明确授权则告知后执行，未覆盖才询问。该授权不等于批准尚未展示的分页、设计、参考用途、生图或成品。
- 有效分页、参考用途、设计变更、明确生图授权、代表页确认和最终定稿 Gate 均保留。用户拒绝重复回答不是同意待决方案；回查批准范围，删除重复问题，只保留真正未决的差异。
- 阶段完成先报告结果；仅当授权已用尽或遇到实质 Gate 时停止。本节限定本文“立即停止/只问是否执行”的适用条件，不能用单步默认覆盖明确端到端授权。出现交互冲突时按需读 `_shared/interaction-gate-rules.md`。
