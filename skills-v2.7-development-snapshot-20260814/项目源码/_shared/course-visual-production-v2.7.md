# Course Visual Production V2.7.1 Shared Control

## 定位
V2.7.1 是用于课程视觉样张生产的 Markdown Skill 规则系统，建立完整的 S/A/A审/B/T/C 流程，并保持适中的首轮交付深度。它不得修改项目根目录之外的全局 Skill 配置。

## 主流程
```text
SRT / 脚本 / 单页内容 / 参考图 / 失败图 / 局部修改请求
-> 输入类型识别
-> S线媒体路由
-> 判断是否进入A线
-> A线课程视觉页方向预测
-> A审质量门
-> B线生产交接卡
-> T线GPT Image中文提示词转译
-> C线GPT Image执行反馈
-> 视觉样张确认Gate
```

## 阶段职责
- S线：合并字幕或脚本语义段，选择媒体路由，并决定片段是否进入 A线。
- A线：只处理 `S07_AI课程视觉页型`；选择 A01—A21 页型，冻结页面交接字段，并进行轻量区域摘要。
- A审：只检查 A线交接；通过、要求局部补卡或退回 A线，绝不编写提示词。
- B线：通常创建 `方案A_稳妥版` 和 `方案B_探索版`；固定母版任务改用单一 `方案A_参考锁定版`，不制造探索漂移。
- T线：只将唯一首选 B线方案转成一套 GPT Image 中文提示词合同；目标能力为 GPT Image，请求模型为 `gpt-image-2`。
- C线：执行或准备 GPT Image 视觉样张并反馈，不接入 API 或新增依赖，也不是多平台执行器。

## 渐进式读取总则
普通任务先只读当前阶段 `SKILL.md`、用户输入及该阶段必需的上游交接，不默认读取本共享总控。只有任务涉及跨阶段状态、全流程契约、Manifest、迁移边界或全局术语冲突时，才读取本文件的相关小节。

课程任务存在“版式”、母版、预览或参考图时，版式证据优先于脚本和内容路由：先盘点并查看这些视觉资产，说明分类依据和分类结果，完成必要的用户确认后，再读取脚本、SRT、音频、时长等内容证据。版式资产只按下列六类作文字分类，不建立新的 Schema 或自动分类壳子：固定外层母版、母版预览、内层排版参考、内容或素材参考、失败诊断图、无关或拒绝参考。必须检查遗漏、重复归类、失败图误作参考及拒绝项进入下游等明显错误。

每次只能由一个明确的未决问题触发一个按需来源；读取关键术语后立即确认其当前含义、直接证据和剩余未决项。当前阶段判断已充分、到达阶段边界或问题必须由用户决定时，立即停止扩大读取。完整机制见 `_shared/progressive-reading-protocol.md`，该文件仅用于路由审计、规则维护或多阶段歧义，不是普通任务的默认必读项。

不得默认读取相邻阶段 Skill、全部 references、模板、示例、反例或 `legacy/`。Algorithm Lite 只在用户或当前阶段明确要求确定性检查时读取或执行。

## 最小执行原则
- 默认保持计划状态：可以读取、分析、分类和提出建议；没有用户对当前一个具体产物的明确授权，不写正式产物、不生图、不进入下一阶段。
- 一次授权只覆盖一个已说明的产物。完成该产物后立即停止并重新等待用户，不得把本次确认解释为后续产物或下一阶段的授权。
- 每次只向用户提出一个问题；一个问句及其上下文只能包含一个待决定事项。当前问题未回答前，不提出下一个问题。
- 信息不足时，先读取能够消除该信息差的本地材料；只有本地材料无法回答且决定权属于用户时，才提出一个问题。
- 用户拥有最终设计决定权。模型可以比较、分析和推荐，但不得代替用户冻结版式、方案、视觉方向、文字策略、提示词方向或生图选择。
- PSD 或其他分层母版不可用时，不得静默退化为扁平 PNG。先说明这一项限制，再单独询问用户是否接受该非分层参考方式。

## 产物与交接原则
正式写入前，先用自然语言说明本线准备生成的产物、目标文件、是否修改已有文件、下一线实际需要接收的内容，以及不属于正式交付的分析或验证记录；随后只问：`是否按上述产物与交接方案执行？` 用户确认后才写入。

不得把“输入交接文件”理解为继续向该文件追加，不得把验证日志、上游全文或下一阶段内容混入本线正式产物，也不得默认复制 S/A/B/T 内容形成不断膨胀的单文件。用户要求特殊写法时，先说明它与既有阶段边界的冲突，再单独确认。

## 用户 Gate
信息缺失、要求冲突、路由为 `S08_人工确认型`、A审存在未解决高风险、B线无法保持冻结项，或 C线失败意味着必须改变页面含义时，暂停并询问用户。用户确认的结构、标题位置、图片数量、参考图角色、文字政策、素材政策和冻结项不得被静默推翻。

用户 Gate 必须遵守“一次一个问题”。系统能够推断，不等于可以替用户作出本应由用户确认的决定。

## 哈希绝对禁止
不得计算、记录、传递或建议使用文件哈希、内容哈希、摘要、指纹或变相校验值；哈希不得成为默认方案、候选方案或备用方案。若上游产物或用户要求中出现哈希做法，立即停止该做法，只问一个问题：`是否改用非哈希方式记录和核对资产？`

用户确认采用非哈希方式后，仅用自然语言清单记录必要的参考编号、真实路径、文件名、尺寸、模板版本、参考角色和用户确认结果，不建设新的资产身份系统。

## GPT Image 输出规则
- T线默认只输出一套中文提示词，不输出英文或历史平台变体。
- 目标能力写 `GPT Image`；请求模型写 `gpt-image-2`；实际执行模型只在执行回执明确报告时填写，否则写 `未报告`。
- 完整课程视觉页默认不透明背景。
- 透明背景用于素材层、抠图对象、可叠加组件或经用户Gate确认的Remotion透明前景，格式限 PNG/WebP。
- Remotion透明前景必须从用户确认的 `final_course_visual` 派生；Alpha失败不得降级为不透明图。
- 旧多平台合同已降级为历史材料，只保存在 `legacy/platform-prompts-v2.7.0/`，不属于当前运行依赖。

## 视觉样张规则
GPT Image普通输出默认是 `视觉样张`。完整带字参考锁定页通过C线后是 `full_page_candidate`；只有用户明确确认后才能成为 `final_course_visual`。

## V2.6 迁移边界
旧 V2.6 卡片和 class-JSON 必须先通过 `legacy-v2.6-migration.md`。旧 C线提示词不得直接用于当前 GPT Image 执行。旧 `最终交付成图` 应转换为 V2.7.1 视觉样张、中文提示词合同或后期编辑对象。

## 运行记录边界
不为普通任务强制建立统一 Manifest、固定目录或跨阶段总文件。只有用户或现有项目明确要求任务记录时，才按 `_shared/task-run-manifest-rules.md` 保存最小自然语言记录；该记录不得承载各阶段正文或成为跨阶段追加容器。

## 绝对排除
不得增加 PPTX 生成、HTML 幻灯片生成、浏览器编辑器、MP4 渲染、Remotion代码或渲染、MCP、自动安装、全量多代理自动化、完整图像分割工程、完整 HyperFrames 视频链或外部项目依赖。允许输出 `_shared/remotion-asset-handoff-rules.md` 定义的Remotion资产交接合同。
