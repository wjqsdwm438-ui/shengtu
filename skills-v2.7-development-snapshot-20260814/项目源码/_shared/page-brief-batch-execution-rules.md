# Page Brief And Batch Execution Rules

## 目的

在A形成明确分页后，以一份页面简报承载该页从A到C的必要决定；源证据不绑定接入时的候选页面身份，避免 A、B、提示转译环节反复改写同一意图。页面简报是页面级交接接口，不是跨页大表、运行 Manifest 或全阶段正文汇编。

## 分页权责与状态分离

- 默认A统一完成输入整理、教学分析、必要承载核验、明确分页和内部复核；取消默认独立S与固定独立A审。S仅为显式兼容输入工具，不先给A一套必须沿用的页界。
- **范围批准是A分析准入条件，分页批准不是A分析前置条件。** 源文证据稳定保留，页界/页数由A依据全文关系与真实承载条件形成；旧候选和旧审核通过不自动继承。
- A内部复核必须查页界必要性、相邻合并、合理替代、衔接及覆盖，不只查单元内部自洽；独立审者仅用户明确要求时执行，触发条件本轮不定义，不新增停止点。
- B只落实具体视觉设计和生产组织；涉及页界、页数、正文归属或教学关系时提供证据交A局部修正，纯实现问题留B。原文和准入未变不重跑S，不默认重启整链，不把设计缺口交给用户补做。
- 分页方案须有源路径/版本、逐字起止（均含）、精确定位、明确页序/页数、拆合比较与承载依据；源引用与页面身份解耦。正式页修订保留旧新映射及有效状态，详见 `_shared/pagination-authority-rules.md`。

## 追加式页面简报

各阶段只维护自己的分区；发现上游错误时退回对应阶段修正，禁止在下游分区另写一个“更正版本”。未适用字段写明“不适用”及理由，禁止保留空白占位符。

```yaml
schema: course_visual_page_brief/v2.7
page_brief:
  page_id:
  original_course_order:
  # 独立源证据与整套分页保存在现有A分析产物；机器校验载荷用a_pagination_plan引用/承载
  a_section:                 # pagination_ref、教学目标/关系、必呈项、图像任务及禁止偏移；内部复核在当前A计划中
  # 旧s_section只作只读历史源引用，不要求新任务创建或冻结S区
  b_section:
    pagination_ref:          # plan_id/plan_version/page_id/owned_spans与A相同
    pagination_feedback: []  # 新分页问题归A；纯实现问题留B
    implementation_evidence: # 能证明、不能证明、最大风险、是否需代表页校准
    main_execution_plan:     # 唯一主方案、模板、内容容器、语义视觉载体和阅读顺序
    skeleton_inheritance:   # no_inheritance，或来源页/同教学关系理由/继承项/必须变化项
    batch_assignment:
    batch_calibration:
    qualitative_visual_checks:
    C_adapter_handoff:
  c_section:
    adapter_preflight:
    compiled_execution_contract:
    execution_record:
    local_revision:
```

课程页码和原始顺序不可因生产批次重排而改变。候选页码不是不可调整的原文顺序；教学分组或执行页拆合必须保留原文顺序并显式记录旧新映射，不原地覆盖已确认对象。最终组装使用原始顺序，不使用批次执行顺序。

## 分页计划和旧合同兼容

整套分页记录放在现有A分析产物中，页面简报仅引用本页所需的源跨度、教学要求与当前版本；不另建全阶段正文总表。`pagination-plan-contract.md` 定义机器检查时的 `a_pagination_plan` 与页级 `pagination_ref`，JSON是可选检查载荷，不是用户必填台账。

新默认workflow为 `A → B → C_adapter → C_generate → assembly`，输入整理与内部复核均在A中。旧S区、旧A审passed和旧固定S/A_review工作流作为历史保留，不自动迁移成已就绪；需要A基于原文和有效范围完成当前方案及内部复核。旧确认只沿用其实际批准对象。

A变更页界时在本阶段维护plan_version、源跨度/旧新页映射和受影响下游状态；B不能另行重分。未变页面只同步必要版本引用并保留有效依据，不因此重审整课。源文件内容未经授权不改写；上下文回指不计作正文二次归属。

页面、页内状态和镜头不自动一一对应。A以现有 `same_screen_reason`、`cross_page_reason` 说明状态先后/并现及必要跨页关系，`required_text_and_labels` 保留本页各状态必呈文字而非全时同屏清单；B在 `reading_order` 落实当前状态及其逐字文字，主方案仍完整收敛。`context_refs` 可引用本次A页拥有的正文作前页回显或后页视觉预览，说明方向、教学作用及非新增旁白，不增加正文归属、不改原旁白顺序，不引用Non-A/批注/批准外文字。必要图解和观察顺序也属于承载，不只测字号。

未验证效果写现有 `unverified_limits`、实现证据和 `open_for_calibration`；完整方案可待首轮校准，核心决策不能留空交C。无匹配案例不阻塞B内容驱动设计，成熟复用不省A判断。字段类型/版本不变，旧静态记录不得自动重释为已验证动态设计，也不新增生成次数或生产步骤。

## 动态批次

B线根据页面实际机制形成批次，不预设课程应有几批。批次边界必须综合检查：外层模板、教学关系、语义视觉载体、参考依赖和生成方式是否足够接近。任一项存在会造成错误继承的实质差异，就应拆批；单页独立成批是允许结果。

以下均不能单独作为同批依据：页码连续、同一章节、同一课程、表面配色相似、上一页效果好。

每批记录：批次临时名称、成员页及课程原始顺序、共同实现依据、不得共享的差异、代表页、代表页选择理由和用户确认结果。批次名称只是当前任务的自然语言标签，不得演变为固定页面分类体系。

## 代表页 Gate

代表页应覆盖该批核心教学关系并具有典型信息密度，不能选择过度简单或只在该批出现一次的特殊页面。执行顺序为：

1. B线完成批次及代表页建议；
2. C线通过适配门槛且取得代表页一次首轮生图授权后，只执行代表页；
3. 用户确认代表页能支撑该批共同机制；
4. B线把确认结果冻结为本批执行合同；
5. C线仅对另获列名各一次首轮生图授权的本批其余页面展开。

代表页确认仅满足该批展开前提，不代替其余页面生图授权，不自动确认该页为 `final_course_visual`，不授权其他批次或图像继承。其结果只有另经 B明确选为当前页骨架参考并有完整继承证明才可附加；共同基准由 B维护，C不得另写一版。

## 批间上下文隔离

同类型机制足够接近才同批；每批使用独立 C线对话或等效隔离上下文。同批在同一 C线对话连续执行，隔离边界是不同批次而不是同批各页。新批次只加载：本批已确认共同机制、当前页面简报、明确选定的真实参考和必要技术合同。不得自动加载上一批生成图、失败图、未选参考、对话历史或其他批次页面。

批内每页使用“固定基准＋本页差异”：共同项写在 B区 `frozen_batch_core`，本页对象、数值、文字、图片和必要区别写在 `within_batch_required_differences` 与 `allowed_to_change`。若差异改变共同机制，拆批或回 B；冻结后不滚动吸收生成结果。历史上下文不是新的指令或参考授权；确已混杂时，只依同一冻结基准恢复干净上下文，不改设计或扩大授权。

批内也不得默认把上一张生成图作为输入。只有页面简报中存在完整骨架继承证明，且该图片被明确列为当前页参考时才能附加。

## C线执行适配器

执行适配器属于 C线内部前置步骤，不产生独立 T线交付。适配器在执行前必须验证：

- 源证据引用、当前A分页/内部复核和B区齐全且无冲突，A/B的pagination_ref与有效方案一致；旧S/A审通过不能替代新方案；
- 输出尺寸、模板、主视觉描述和语义视觉载体全部非空；
- 列出的本地素材可读且获准用于当前用途/范围，参考角色和实际附加清单一致；待批、禁用、未选参考不得进入附件；
- 保留项、仅修改项和禁止修改项明确，当前实际状态及其文字分配由B明确，C不猜测；
- 批次代表页 Gate 已满足，或当前执行对象本身就是待确认代表页；
- 骨架继承存在时已完成语义证明；
- 没有固定图片比例或由画布尺寸推导出的占比指令。

任一必填项为空、素材不存在或规则冲突时必须停止并回到责任阶段；禁止由 C线猜测补齐。通过后只输出一套结构清晰的中文执行提示和实际资产附加清单。

明确无外部资产时，用现有字段形成显式分支：B `asset_used: []`、`outer_template.evidence_reference_id: no_external_asset`；C `template_identity.evidence_reference_id`/`master_asset_path` 均为 `no_external_asset`、`master_asset_exists_and_readable: no`。选定参考、编译references与实际附件均为空，未执行不虚填回执，既有description/实现证据写明无外部资产及理由。主视觉、校准与授权Gate不豁免；token不是路径，不可掩盖缺失文件或绕过参考锁定任务的真实主参考要求，不新增schema或字段。

## 局部修改与退回

C线局部修改必须显式写明保留项、仅修改项和禁止修改项。只要修改不改变教学关系、模板或核心骨架，可在 C线完成；一旦需要改变任一项，停止继续重抽；教学/分页问题回A，模板/骨架实现问题回B。原文定位、时间码、素材对应及页界/页数、正文归属、教学目标/关系或必须项错误回A；纯模板、骨架与参考实现问题回B。

只有确认仅本页局部失败且共同依据无误时，记录该页后才可继续其他已授权页，不自动补生成。共同依据出错或影响不明，先暂停可能依赖它的页，按最早责任回 A/B/C；不默认全课停工。

不得使用无限次整页重抽来解决上游设计问题。既有完整带字页的局部文字修订上限仍按当前 C线合同执行。

## 非比例质量检查

任何页面类型都不得绑定固定图片占比。检查图像教学任务、视觉焦点、文字可读性、阅读顺序、信息关系、背景竞争和必呈内容空间；输出分辨率只属于技术规格。

C只对照本次实际生成状态的必呈文字与必要图解验收，不把整页/整个教学任务各状态清单塞进一张图。静态样张不证明未生成状态、切换、运动或跨状态阅读效果；未验证条件在现有反馈如实注明，代表页通过不自动消除它们。

B既有 `reading_order`/`text_realization_strategy`/`main_visual_description` 须完整映射全部A必呈项、当前执行状态和其他状态去向，`must_show_text_verbatim` 只列当前图准确文字；不以“动画稍后再补”掩盖设计空白。当前状态成图与全页媒体完成分开，单张通过不释放未验证状态或冒称整页/批次通过。可用页ID加状态后缀追溯实际文件，不改page_id或新增生产阶段。

B方案可行性检查、C逐图实际验收、C批后共同基准检查是三个不同动作。每页都须对照原文、A/B冻结要求与实际图像完成 C检查，不能用生成者自述或代表页通过代替。

批后在现有反馈中横比代表页、边界/高密度页与后续输出，检查模板、标题系统、共同载体及参考角色是否漂移；同时核对对象、数值、关系细节等必须差异确实保留，不以“都长一样”为通过依据。记录通过页、问题页、共因及影响范围；个别执行偏差回 C该页，错误继承/共同设计回 B，源证据/分页/语义错误回A，只重查依赖同一错误的页。检查无需另问，改冻结项、换参考或重新生成仍须相应授权；通过不等于用户定稿。

## 原顺序组装核对

把通过检查的产物、Non-A片段及已有媒体恢复到 `original_course_order`，核对数量、页码、缺页、重复、错序、错版、媒体真实可用状态与对应位置，以及跨页指代/叙述连续性。生产批次顺序不得泄漏到课程顺序，原片段均须有去向，Non-A不能消失。

在现有交付清单/包中列明候选、已确认定稿和未完成项；用户可明确列页一次确认最终范围，不要求逐页重复确认。未确认只按样张/候选交付，有缺项不得冒称整课完成，待批 AE不得混入。组装仅组织已有产物，不重设计、不改删原文，不新增视频渲染或可编辑课件工程。

纯排序/文件映射错误在组装处修正；源材料证据与跨页分页/语义回A，设计一致性回 B，图像问题回 C；只重查受影响页及必要相邻衔接。

## 试运行评价

先完成规则及反例走查；真实试运行在具体页/批次生图授权内选择典型页、边界/高密度页、同批连续后续页及必要不同批次，页数依材料和授权确定，“约20页”不是硬门槛。记录首次可用、返工原因、修改次数、用户介入、跨页错误继承、同质化与语义偏移；所有单页检查后再横比批次。只有存在可比旧基线时才报告改善，否则仅报告绝对结果；离线字段检查不能证明教学正确、真实批准或图像效果。只调整有失败证据的范围，不固化批数、页型或评分平台。
